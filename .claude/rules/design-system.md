# Design system styles

- Styles are Linaria `css` blocks in the component file, real CSS with tokens only. Variants are objects of `css` classes; cross-part rules use the exported class (`.${other}`), `&` nesting, `data-*` and `aria-*`.
- A component file past 200 lines moves its blocks to `<name>.styles.ts` beside it, with named exports.
- The design system lives inside `web/app`: parts in `src/components/`, tokens in `tokens/` (source) and `tokens/design-tokens.css` (generated by `npm run tokens`, never edit), stories beside each part and in `src/stories/`. `npm run storybook` shows them.
- Six parts have a `-next` folder (`button-next`, `chip-next`, `date-field-next`, `sheet-next`, `toast-next`, `todo-row-next`). They are the Linaria version of a part the app still draws in plain CSS. When a slice moves a family, the `-next` folder replaces the old folder and drops the suffix.
- Plain CSS stays only in the generated tokens file and `src/styles/design-base.css` (Storybook resets, fonts). Run-time values are CSS variables set on the element.
- `func-style` and three jsx-a11y rules are off for the parts not yet adopted (see `overrides` in `web/app/.oxlintrc.json`). Remove a folder from that list when you move it to function declarations.
